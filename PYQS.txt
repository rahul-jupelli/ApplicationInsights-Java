Scenario-based answers
Q1. After setting up the GitHub webhook, Jenkins does not trigger automatically. What simple check
should be performed on ngrok?
Check that the ngrok terminal session is still running and shows an active HTTPS forwarding URL pointing to the
local Jenkins port (usually localhost:8080). If ngrok has stopped, GitHub cannot reach the local Jenkins server
through that tunnel.
Q2. How does Jenkins display compilation errors in the console output when a Java syntax mistake is
made?
The Maven build output in Jenkins Console Output shows a compilation failure, usually including the Java source
filename, line number, and compiler error description. The build is marked as FAILURE.
Q3. If Maven compiles files successfully but a unit test fails, will Jenkins still create the WAR file?

In a pipeline where the Test stage runs before Package and the pipeline stops on a failed command, no. Maven
reports the test failure, Jenkins marks the build as FAILURE, and the later Package stage is skipped. If the
pipeline is deliberately configured to ignore test failures or continue after failure, behavior can differ.
Q4. Why is ngrok necessary when connecting a local Jenkins server to GitHub webhooks?
A Jenkins server running on localhost is not directly reachable from the public internet. Ngrok creates a public
HTTPS tunnel that forwards GitHub webhook requests to the local Jenkins server.
Q5. What is the difference between Continuous Integration and Continuous Deployment?
Continuous Integration (CI) means developers frequently merge changes into a shared repository and each
change is automatically built and tested. Continuous Deployment means changes that pass the required
checks are automatically released to the production environment without a manual deployment approval step.

Scenario-based answers
Q1. The container runs on port 8090 inside EC2, but the browser URL uses port 8080. What error occurs
and which AWS setting must be updated?
The browser may show a connection-refused or timeout error because the URL uses the wrong host port. With
the specified mapping -p 8090:8080, browse to port 8090. Ensure the EC2 Security Group has an inbound TCP
rule for port 8090. The container's internal port and EC2 host port are different.
Q2. Why is leaving SSH port 22 open to everyone (0.0.0.0/0) a security risk?
It allows any internet host to attempt SSH connections to the instance. This increases exposure to password/key
attacks and attempts to exploit SSH vulnerabilities. Restrict SSH to trusted IP addresses, such as My IP, and use
key-based authentication.
Q3. What basic Linux commands refresh packages and install Docker on Ubuntu?
Use: sudo apt update, sudo apt upgrade -y, sudo apt install docker.io -y, sudo systemctl
start docker, and sudo systemctl enable docker. Verify with docker --version.
Q4. If Tomcat crashes inside the running container, how can its logs be viewed?

Run docker logs apartment-container. To follow new log output continuously, run docker logs -f
apartment-container. These logs can show startup errors, application exceptions and other diagnostic

Q5. How can application availability be improved?
Run multiple application instances, place a load balancer in front of them, use health checks and automatic
restart/recovery, monitor resource usage, maintain backups, and deploy across multiple availability zones where
appropriate. A single EC2 instance remains a single point of failure.

Scenario-based answers
Q1. If one application pod crashes, how does Kubernetes maintain the required number of replicas?
The Deployment controller manages a ReplicaSet, which continuously compares the actual number of pods with
the desired replica count. If a pod stops, the controller creates a replacement pod to restore the desired count.
Q2. What is the difference between a Pod IP and a Service IP?
A Pod IP belongs to an individual pod and can change when that pod is recreated. A Service provides a stable
virtual IP and DNS name that routes traffic to the matching healthy pods.
Q3. Which kubectl command checks the list of pods and their statuses?
kubectl get pods. It displays pod names, readiness, status, restart count and age.
Q4. If the NodePort page cannot be opened directly, what kubectl port-forward command can test the app
locally?
Use kubectl port-forward service/apartment-service 8080:80, then open
http://localhost:8080/ while the command remains running.
Q5. How can Nagios identify application failure when the server is running?
Configure an application-level service check, such as an HTTP/HTTPS check, to verify that the web endpoint
responds as expected. The server may be up while the application is down; Nagios can report a service failure
when the HTTP check fails or returns an unexpected result.

Do not run docker compose down -v if you want to preserve the named volume. The -v option removes named volumes

The --build flag asks Compose to build the image before starting/recreating services. If source code is copied into
the image, the new image is needed for changes to appear.
Scenario-based answers
Q1. What is the main use of depends_on in docker-compose.yml?
depends_on defines service startup dependencies. It tells Compose to start a dependency before the dependent
service. With a supported health condition such as service_healthy and a configured health check, Compose can
wait for the dependency to become healthy before starting the dependent service.

Q2. Why configure persistent volumes for databases, and what happens if volumes are left out when
docker compose down is run?
A persistent volume stores database files outside the container's writable layer, so data survives container
removal and recreation. Without a persistent volume, data stored only in the container filesystem is lost when that
container is removed. A named volume normally remains after docker compose down; docker compose down -v
removes Compose-managed named volumes.
Q3. Why may code changes not appear after docker compose up -d, and what flag should be added?
The running container may still be using an image built from the old source code. Use docker compose up -d
--build to rebuild the image and start/recreate the services with the updated image.
Q4. How do custom networks help containers communicate using names instead of IP addresses?
Containers attached to the same user-defined Compose network can use Docker's internal DNS service
discovery. The web container can connect to the database using the Compose service name, such as db, rather
than a changing container IP address.
Q5. How can database information be recovered after container deletion?
If the database used a persistent named volume, recreate the database container and attach the same volume.
PostgreSQL can then read the previously stored database files. If no volume or backup exists and the only copy
was inside the deleted container, recovery may not be possible.
